Android ptrace 反调试技术
│
├─ 一、主动占坑型
│  ├─ 1. 自附加 (TRACEME)
│  │      └─ 箭头标识：自身 → 父进程(zygote)
│  │
│  └─ 2. 子进程附加父进程
│         └─ 箭头标识：子进程 → 父进程
│
├─ 二、被动检测型
│  ├─ 3. TracerPid 检测
│  │      └─ 箭头标识：进程 → /proc/self/status
│  │
│  ├─ 4. 进程状态 (stat) 检测
│  │      └─ 箭头标识：进程 → /proc/self/stat
│  │
│  ├─ 5. wchan 检测
│  │      └─ 箭头标识：进程 → /proc/self/wchan
│  │
│  └─ 6. 系统调用时间差检测
│         └─ 箭头标识：进程 → 自身系统调用
│
└─ 三、衍生对抗型
   ├─ 7. 双进程互相守护
   │      └─ 箭头标识：子进程 ⇄ 父进程
   │
   └─ 8. 反 ptrace 附加（拒绝调试器 attach）
          └─ 箭头标识：自身 → 任意进程（如 PID=1）

Android 双进程守护中的 ptrace 反调试
│
├─ 0. 前置澄清：双进程守护 ≠ ptrace 反调试
│    ├─ 双进程守护 = 两个进程互相监控、互相拉起（主要目的：保活）
│    └─ ptrace 反调试 = 利用 ptrace 占坑，阻止外部调试器附加（主要目的：反调试）
│        └─ 两者常结合使用：一个进程（子）ptrace附加另一个（父），同时实现保活+反调试
│
├─ 第1层：核心目标
│    └─ 防止外部调试器（Frida/gdb）通过 ptrace 附加到主进程
│
├─ 第2层：核心手段 —— ptrace 占坑
│    │
│    ├─ 原理：Linux 内核限制，一个进程同时只能被一个 tracer 通过 ptrace 附加
│    │
│    ├─ 实现步骤
│    │    ├─ 1. 主进程启动
│    │    ├─ 2. fork() 创建子进程
│    │    └─ 3. 子进程执行 ptrace(PTRACE_ATTACH, 主进程PID)
│    │        └─ 结果：主进程的 ptrace 槽位被自家子进程占满
│    │
│    └─ [!] 错误纠正：ptrace 反调试的核心 = ptrace 系统调用，与 pthread_create 无关
│
├─ 第3层：增强监控 —— pthread_create 反检测线程（可选）
│    │
│    ├─ 目的：检测 ptrace 槽位是否被“别人”抢占，或发现调试器痕迹
│    │
│    ├─ 常见监控内容
│    │    ├─ 读取 /proc/self/status → 检查 TracerPid
│    │    ├─ 读取 /proc/self/maps → 搜索 frida-agent.so 等特征
│    │    ├─ 遍历 /proc/self/task/ → 查找异常线程名（gmain, gum-js-loop）
│    │    └─ 使用 inotify 监控 /proc/pid/mem 访问
│    │
│    └─ [!] 错误纠正：pthread_create 不是 ptrace 反调试的原理，而是“反反调试”的监控手段
│
├─ 第4层：防御触发行为
│    └─ 一旦检测到异常
│        ├─ 立即自杀（exit / kill）
│        ├─ 死循环阻塞
│        └─ 或触发进程间互相 kill
│
└─ 第5层：绕过方法（分层独立手段，按优先级/难度排列）
     ├─ 【必要前置】spawn 模式
     │    └─ A. 使用 frida -f <package> 抢占 ptrace 槽位，返回-1
     ├─ 【核心三件套】—— 应对绝大多数检测
     │    ├─ B. Hook ptrace（防止 App 因自附加失败而自杀）
     │    │    └─ 对 PTRACE_TRACEME 返回 0
     │    ├─ C. 篡改 /proc/self/status（隐藏 TracerPid）
     │    │    └─ Hook open/read，替换 TracerPid: xxx → 0
     │    └─ D. 篡改 /proc/self/maps（隐藏 frida 内存特征）
     │         └─ Hook fgets/open/read，过滤 frida 相关行
     │
     └─ 【可选增强 · 独立暴力手段】
          └─ E. Hook pthread_create
               ├─ 作用：让所有反检测线程根本无法创建
               ├─ 特点：暴力、一刀切、独立可用
               └─ 说明：可以不配合 C/D 单独使用；与 C/D 互为替代或叠加
